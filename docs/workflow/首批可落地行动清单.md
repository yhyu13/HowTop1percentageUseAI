## 游戏开发组

**#4 用 TapTap 制造 7 天做一款融合玩法小游戏**
- 做法：完全复刻出头喵模式——2 天出可玩原型（玩法融合，如"小丑牌 × 2048"式的两个已验证机制嫁接）、其余 5 天内容填充与美术包装；第 1 天就准备图标/宣传图/小红书组件素材（首发 3 天黄金窗口不可浪费）。
- 验证指标：是否上架、新品榜/曝光数据、以及"程序岗被 AI 替代"的手感评估。
- 依据：金浩斌 TDW2026 演讲（http://www.gamelook.com.cn/2026/08/599286/）；TapTap 论坛一人复盘（https://www.taptap.cn/moment/853728463025082019）。

**#6 给 web 游戏加一个"AI 试玩员"**
- 做法：Playwright 打开游戏 + LLM 按四阶段评估（加载→控制发现→玩法探索→质量评分），直接参考开源 GameEval 的管线设计；接入 #3 的定时任务每晚跑。
- 依据：GameEval（https://github.com/adam0white/GameEval）；FSE 2025 LLM playtest 论文（https://dl.acm.org/doi/abs/10.1145/3696630.3728700）。

## AIGC 组

**#5 建美术资产库**
- 做法：一个 git 仓库管理四件套——① 提示词模板（正负向成组，参考 prompt-concatenate-pro 的组织法）② 风格 LoRA/参考图（Midjourney style reference）③ 固定 seed 记录表 ④ ComfyUI 工作流文件版本化。每次产出好图，回写资产条目。
- 依据：ComfyUI 提示词资产节点生态（https://github.com/2223290690z-hue/comfyui-prompt-library-nodes 、https://github.com/StoneZol/prompt-concatenate-pro）；歸藏 prompt 仓库（https://github.com/op7418/guizang-s-prompt）。

## 产品组

**#7 用 S1–S4 材料法写 tutor 项目第一版 PRD**
- 做法：严格按墨刀三步——先备四份材料（S1 范围/S2 内容样本/S3 业务规则/S4 不做清单），先让 AI 提问并输出"已知/缺失/不做"三栏，分三次生成（输入整理→规则流程→异常验收）。S2 直接用自己的学习笔记当课程样本。
- 铁律：每条需求指回材料；AI 不得补造数据；未决事项进清单。
- 依据：墨刀 AI PRD 教程（https://modao.cc/ad/blog/ai-prd-tutorial-for-pm.html）。

## 投资组

**#8 搭个人投研流水线**
- 做法：照抄 AlphaInsight 结构的最小版——3 个 Agent（规划拆意图树 / 检索并发查源 / 做空挑刺辩论）+ 1 个主笔（输出带段落级引用的报告）。信息源先手工维护 20 个一手来源清单（公司公告/论文/官方博客），后续再自动化爬取。
- 纪律：每个结论可点击回原文；永远保留"敌方 Agent"。
- 依据：AlphaInsight（https://github.com/Robot-Nav/AlphaInsight）；n8n 尽调模板（https://n8n.io/workflows/13501/）。

## tutor 创业组

**#9 tutor MVP：BKT 掌握度 + 苏格拉底护栏**
- 做法：选一个极窄人群（建议：游戏开发者学某项具体技能，你自己的路径即内容壁垒）；最小技术栈 = RAG（限定内容 + 引用定位）+ 每知识点一个掌握概率（BKT 最小实现，开源参考 ai-engineering-from-scratch capstone）+ 护栏（不直接给答案，先问后说）。每个会话结束输出掌握度变化。
- 红线：只报告掌握度数据，不承诺提分；内容只依据自己的课程资料回答（与 #7 的 S3 规则同构）。
- 依据：05 篇全部来源；Khanmigo skill gating 论文（https://qu3ry.net/articles/llm-skill-gating-khan-academy.pdf）。

## 自身编程组

**#1 给所有工作目录建"宪法"**
- 做法：游戏仓库、学习笔记库、tutor 项目各一份 CLAUDE.md/AGENTS.md：技术栈约定、目录结构、绝对禁止事项、验收标准；逐月追加自己的"踩坑条款"（歸藏的护栏文件方法论：保护上下文与接口）。
- 依据：Claude Code 官方 memory 文档（https://code.claude.com/docs/en/memory）；歸藏访谈（https://www.163.com/dy/article/KSNFVMK60511B6FU.html）。

**#2 落地 Karpathy 四准则**
- 做法：把"编码前先思考/极简优先/外科手术式修改/目标驱动执行"四条原文抄入 CLAUDE.md；每两周复盘一次 diff，看是否有"顺手优化"和"过度设计"的违规案例。
- 依据：社区实测 65–70% → 91–94%（https://cloud.tencent.com/developer/article/2672609）。

**#3 上线"睡前派活"定时任务**
- 做法：晚上把任务拆成 ≤10 个 pass 写进计划文档，交给定时任务（凌晨自动执行 + 跑测试 + smoke test），早上只做审核。计划文档越细，出问题越少（歸藏：70% 时间应花在调研与计划）。
- 依据：歸藏访谈（同上）；Anthropic 子 Agent 模式（https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents）。

## 底座·获客组

**#10 把学习过程公开化**
- 做法：选定一个主阵地（小红书/即刻/X 三选一起步），把 #4–#9 的过程按周公开（数据、失败、模板）。目标不是涨粉，是验证"内容 → 信任 → 首批 tutor 种子用户"的通路。图文之外优先练短视频（歸藏判断：AI 洗稿使图文商业价值走低，视频不可回避）。
- 依据：Photo AI "收入截图就是营销"（https://aituts.com/case-study/photo-ai-pieter-levels/）；歸藏 2025 年度回顾（https://m.163.com/dy/article/KI24JDV30556BM3X.html）；TapTap 论坛"缺的是分发不是产品"（https://www.taptap.cn/moment/853728463025082019）。

## 建议节奏

- 第 1–2 周：#1 #2 #5 #7（纯建系统，零风险）
- 第 3–4 周：#4 #6 #3（游戏流水线打通）
- 第 5–8 周：#9 #10（tutor MVP + 内容冷启动）
- 持续进行：#8（投研流水线按周跑，本身也是 tutor 项目的元方法验证）

> 一句话总结：前 1% 用户的秘密不是更聪明的提示词，而是**把自己活成一个系统**——宪法、记忆、子 Agent、定时任务、资产库、公开飞轮。以上 10 条就是这个系统在你的六个领域里的最小安装包。
