# 02 · AI 即公司与超级个体：一人 + AI 编排替代小团队

> 覆盖方向 2。人物画像附于文末（更细的可后续放 `docs/profiles/`）。

## TL;DR

1. "一人 + AI 编排"在收入端已被多个独立案例验证：Photo AI 单人 $100k+/月（毛利 85%+）、Base44 六个月被 $8000 万现金收购、seeu.food 一人一个月赚 $90k；Sam Altman 公开预言第一个一人十亿美元公司会"比所有人预期更早到来"。
2. 共同方法论可总结为**"一人公司飞轮"**：小切口需求 → 极速上线（天/周为单位）→ 从第一天收费 → 公开数据做营销 → AI 承担执行、人保留判断与品味。
3. 护城河发生了迁移：模型不是护城河（开源权重人人可下载），**分发、信任、垂直数据、个人品牌才是**；见u.food 一个月后被 2–30 个克隆卷死的教训。
4. 组织形态上出现"AI 员工团队"范式：一个决策者 + 规划/检索/分析/风控等专职 Agent 分工，甚至出现"1 人管 50 个 Agents"的实践者。
5. 国内政策面开始响应（江苏试点"1 个人 + AI 就能开公司"），中文圈"超级个体"叙事已从自媒体口号进入真实经营阶段（歸藏：一人运营 9 个平台 + 2000 人付费社群）。

## 一、标杆案例（按证据强度排序）

### 1.1 Pieter Levels / Photo AI（海外，可审计性最强）

来源：https://aituts.com/case-study/photo-ai-pieter-levels/ （该文数字均出自 Levels 在 X/播客的自述，经 Indie Hackers、ppc.land、Lex Fridman 播客交叉整理）

- 2023-02-10 上线，首周收入 $5,400；2023-04 月入 $28.7k；2024-09 突破 $100k/月；2025 年公开数据在 $105k–$132k/月区间波动。**零员工、零投资人**。
- 技术栈反直觉地"土"：单个大 PHP 文件 + SQLite + 一台服务器；模型训练与推理租 Replicate 的 GPU（规模期约 $12k/月），毛利 85%+；定价 $19–$199，主力收入来自 $49–$99 档。
- 获客：约一半流量来自 X——**收入截图就是营销**；Lex Fridman 播客一次出现带来可见尖峰；无付费投放。
- 方法论四件套：最快上线最丑可用版、第一天就收费、公开数字、把算力当 COGS 定价（先算单次生成成本再定价）。
- 关键判断："模型不是护城河，包装才是"——明确的承诺（"你的照片级写真"）、小白能走完的训练流程、从第一天就挂价格。

### 1.2 Base44 / Maor Shlomo（海外，退出验证）

来源：https://cloud.tencent.com/developer/article/2538775 （InfoQ 中文站转采，含 Lenny's Podcast 一手访谈内容）

- 成立 6 个月被 Wix 以 8000 万美元现金收购；用户 25 万（成立 3 周即破 1 万，后至 40 万且零营销费用）；盈利——付完大模型 token 成本后 5 月单月利润 $189k。
- 创始人 31 岁，曾联合创办 Explorium（融资 1.25 亿美元、100+ 员工），这次刻意选择"轻装"：vibe coding、三人小团队、不做巨无霸。
- 产品差异点："电池内置"（batteries included）——数据库/用户系统/分析全部内置，用户一句话生成全栈应用，无需配 API 密钥。
- 反常识实践：**删除"有用"的功能反而让激活率翻倍**；优化代码仓库结构以提升 AI 代码生成效率；三个月不写一行前端代码。

### 1.3 阴明 / seeu.food（国内出海，冷静样本）

来源：https://developer.volcengine.com/articles/7589192954821279770 （Vibe Coding 黑客松现场播客分享的整理，当事人一手）

- 掘金创始人、离开字节后作为"超级个体"下场：iOS 健康饮食 App（拍照算卡路里/拍冰箱推荐菜谱），目标美国市场 80–90% 白人女性 lifestyle 用户。
- 成绩：总收入接近 9 万美金；订阅 $9–15/月，单次图片识别成本约 $0.0001（GPT-4.1/Flash），毛利极高。
- 冷启动：不投广告不做矩阵，**Reddit 高 karma 账号一个一个私信**是唯一有效渠道（发帖会被删、评论效率低）——"非常超级个体化"的获客方式，团队做不了、个人恰好合适。
- 教训：第 1 个月红利期、第 2 个月同类激增（2–30 个几乎一样的 App，不少是中国团队）、第 3 个月卷死。结论：**"如果你在出海做的是一个对的点子，千万别 Building in Public"**；独立开发者尽量别做 App（iOS 审核、健康类合规、单人扛不住）。
- 趋势判断："只存在 7 天的软件"会成为新常态；真正的机会在极度下沉的真实需求（例：小饭馆手写点单 → OCR → LLM 拆解菜品 → 原料推理 → 备货建议——"以前只有 7-11 用得起的能力，现在小饭馆也用得起"）。

### 1.4 出头喵工作室 / 金浩斌兄弟（国内游戏，见 03 篇详述）

- 2 人（策划 + UI 美术，均不会编程）+ TapTap Maker，4 个月 4 款游戏；"AI 就像我们的第三胞胎兄弟"。来源：http://www.gamelook.com.cn/2026/08/599286/

### 1.5 舆论与政策面

- Sam Altman：一人十亿美元公司会"sooner than anyone expected"，预计 2028 前后出现；组织架构将塌缩为"一个人类战略家 + Agent 网络"。（https://uk.entrepreneur.com/en-gb/entrepreneurs/the-billion-dollar-company-of-one/500329）
- Forbes：OpenAI 提出 one-person AI startup 概念后已有三位创始人做出实证（https://www.forbes.com/sites/sandycarter/2026/04/04/openai-called-the-one-person-ai-startup-and-three-founders--proved-it/）。
- 国内政策：江苏推出"1 个人 + AI 就能开公司"的试点报道（https://finance.sina.com.cn/wm/2025-11-12/doc-infxaxmi3665384.shtml）；企业服务侧出现"把 20 年经验封装成永不下班的同事"的一人公司新范式讨论（https://www.toutiao.com/article/7637417540439769640/）。
- 学术侧：IEEE 已有《AI-Driven One-Person Companies》论文研究该形态（https://xplorestaging.ieee.org/document/11578160）。

## 二、可迁移的"AI 即公司"运营模型

综合上述案例，前 1% 超级个体的公司结构高度一致：

```
              ┌─────────────── 你（CEO/品味/决策）───────────────┐
              │  定方向 · 挑质量 · 做判断 · 维护信任资产           │
              └───────┬───────────────┬───────────────┬────────┘
                      │               │               │
              ┌───────▼──────┐ ┌──────▼───────┐ ┌─────▼────────┐
              │ 生产 Agent 群 │ │ 获客/内容流水线 │ │ 经营 Agent 群  │
              │ 代码/美术/音频 │ │ 多平台分发/私信 │ │ 财务/客服/数据  │
              └──────────────┘ └──────────────┘ └──────────────┘
                      ▲ 共同底座：CLAUDE.md 宪法 + 知识库 + 定时任务
```

五个可复制的经营原则（每条都有案例出处）：

1. **先有分发再有产品**：Photo AI 靠 X 粉丝冷启动、seeu.food 靠 Reddit 私信、金浩斌靠 TapTap 免费曝光、TapTap 论坛开发者复盘的结论是"缺的是分发、不是产品"（https://www.taptap.cn/moment/853728463025082019）。
2. **把算力当成本项设计毛利**：Photo AI 的 COGS 定价法；Base44 公开记录 token 成本。
3. **速度即护城河的贴现**：红利窗口以月计（seeu.food），所以上线周期必须以天/周计（Base44、TapTap Maker 案例）。
4. **公开与匿名的取舍**：海外超级个体用 Build in Public 换流量，出海套利型项目反而要藏（阴明的一手教训）。
5. **人只做不可委托的三件事**：方向判断、质量品位、信任关系（与 01 篇歸藏"三大能力"互相印证）。

## 三、"AI 员工"编排的当前实践水位

- 个人级：歸藏的"睡前派活、凌晨执行"定时任务矩阵；独立开发者用 AI 智能体矩阵"一个人干三个人的活"的案例报道（https://cloud.tencent.cn/developer/article/2713876）。
- 团队级：What's Next 播客"1 人公司管 50 个 Agents"（https://podscan.fm/podcasts/whats-nextke-ji-zao-zhi-dao/episodes/1-ren-gong-si-kang-5-ge-ren-de-huo-hai-yao-guan-50-ge-agents-s10e18）；TapTap 制造宣布未来要做"一个 Agent 对话 + 多个 Agent 做事"的后台结构（https://news.17173.com/content/02072026/023954968.shtml）。
- 商业模式：超级个体普遍采用"订阅制 SaaS + 广告分成（IAA）+ 付费社群/内容"三种变现的组合（Photo AI 订阅、金浩斌 IAA、歸藏 2000 人付费社群）。

## 五、对用户的落地意义

- 你的 tutor 创业项目天然适合"一人公司飞轮"：小切口（例如"游戏开发者的英语/技术学习 tutor"这类极窄人群）→ 周级上线 → 第一天收费 → 公开构建过程换信任。
- 警惕 seeu.food 陷阱：tutor 类产品同样容易被大厂功能覆盖（豆包免费问答），所以切入点必须绑定"你独有的数据/场景/信任"——比如你自己的游戏开发学习路径本身就是内容资产。
- 游戏侧可立即复用金浩斌模式：先在 TapTap 制造上用 7 天做一款融合玩法小游戏验证手感，把"程序"这个岗位从团队里永久外包给 AI。
